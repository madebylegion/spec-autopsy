# Implementation Plan

Each task is small enough for one call and ends with its own tests. Tests live in `tests/parser/`, `tests/indexer/` and `tests/linker/`; helpers in `tests/helpers/`; fixtures in `tests/fixtures/`. Run tests with `npx vitest --run` and type check with `npx tsc --noEmit`. Do not commit a nested `.git`. No new dependencies are needed. Never change THRESHOLD or any `expected.json`. Do not open `tests/fixtures/heldout/`.

- [ ] 1. Tasks.md reader and task commit subject matcher
  - Add `TaskCommitSubject`, `TaskRequirementRef` and `TaskEntry` to `src/parser/types.ts` as in design.md.
  - Create `src/parser/task-commit-subject.ts` (`matchTaskCommitSubject`) and `src/parser/tasks-reader.ts` (`parseTasksText`, `parseTasksProject`), and export them and the new types from `src/parser/index.ts`.
  - Add `tests/parser/task-commit-subject.test.ts`: both subject forms, case-insensitive `KIRO:` and `Task`, uppercase spec rejected, `kiro: spec linker (requirements, design, tasks)` rejected, no number, non-integer number, empty title, no prefix, trimming. Property with fast-check: generated subjects of both forms are accepted with the same spec, number and title; strings that do not start with `kiro:` are rejected; no string makes it throw.
  - Add `tests/parser/tasks-reader.test.ts`: `[ ]`, `[x]`, `[-]` task lines; sub-lines and sub-tasks belong to the task; a first-column heading ends a task; a requirements line with and without the list marker; bare `1.1` read as `<spec>/R1.1`; several requirements lines joined; duplicate ids dropped; no task line gives `[]`; a missing `.kiro/specs` gives `[]`; `parseTasksProject` on a temp directory with two specs lists them by spec name; the `tasks.md` of this repository's `linker` spec gives its 4 tasks with their ids.

# Implementation Plan

Each task is small enough for one call and ends with its own tests. Tests live in `tests/linker/`; fixtures in `tests/fixtures/`. Run tests with `npx vitest --run` and type check with `npx tsc --noEmit`. Do not commit a nested `.git`. No new dependencies are needed.

- [x] 1. Types, tag extractor and attachment rules
  - Create `src/linker/types.ts` as in design.md (body map types, `TagHit`, accuracy types).
  - Create `src/linker/tags.ts`: `TAG_PATTERN`, `findTags`, `tagsInFile` (containing-symbol rule with innermost choice, 3-line look-ahead after the comment end, test-case rules, title tags, multi-line block comments).
  - Add `tests/linker/tags.test.ts` with example tests built from hand-written `FileIndex` objects: tag inside a symbol range; innermost symbol (method inside class); JSDoc right above a declaration; tag more than 3 lines above attaches to nothing; multi-line block comment line arithmetic; case sensitivity and the left boundary (`Xlinker/R1.1` is not a tag); test-file comment on the same line and 3 lines before a test case; title tag; no cross-attachment between test and non-test files; unknown ids are returned as hits and left to `link` for diagnostics.
  - _Requirements: linker/R1.3, linker/R2.1, linker/R2.2, linker/R2.3, linker/R2.4, linker/R2.5, linker/R2.6, linker/R2.7, linker/R2.9_

- [x] 2. Tokeniser, overlap score, THRESHOLD and their properties
  - Create `src/linker/overlap.ts`: `THRESHOLD = 0.5`, `STOPWORDS`, `tokenise`, `requirementTokens`, `symbolTokens`, `sharedCount`, `overlapScore`, `overlaps` exactly as in design.md, with the formula in a comment.
  - Add `tests/linker/overlap.test.ts`: examples for camelCase, snake_case, `Class.method`, stopwords, short tokens, trailing `s` (including `ss` and `ands`), duplicates, empty input, `THRESHOLD === 0.5`, the 2-shared-token minimum (1 shared of 1 is not a link), score 0.4 below and 0.5 at the threshold.
  - Add properties with fast-check in the same file: `tokenise` never throws and `tokenise(tokenise(s).join(" "))` equals `tokenise(s)`; `overlapScore` is within 0..1 and `overlapScore(a, b) === overlapScore(b, a)`.
  - _Requirements: linker/R3.2, linker/R3.3, linker/R3.4, linker/R3.5, linker/R3.6_

- [x] 3. Planted fixture, classification and `link`
  - First write `tests/fixtures/planted/expected.json` from the plan table in design.md (4 ghosts, 4 unproven, 5 zombies, as `{ "class", "key" }` entries). Only then create the rest of the fixture as plain files, no `.git`: `.kiro/specs/stock/requirements.md` and `.kiro/specs/orders/requirements.md` (14 EARS requirements, `<spec>/R<N>.<M>` numbering), `src/stock.ts`, `src/orders.ts`, `src/shipping.py`, `tests/stock.test.ts`, `tests/orders.test.ts`, `tests/test_shipping.py`, with the decoys and negatives listed in the plan. Check each row by hand against the tokenise rules. Never edit `expected.json` afterwards; if the linker disagrees, report it.
  - Create `src/linker/classify.ts` and `src/linker/link.ts` per design.md: tags first, overlap only for requirements without an explicit link on that side, every passing candidate linked, `lastCommit`, zombies, diagnostics merge (`unknown-requirement-tag`, parser and indexer passthrough), sorting, counts, duplicate requirement ids.
  - Add `tests/linker/classify.test.ts` and `tests/linker/link.test.ts` with example tests on a few small hand-written inputs: ghost, unproven and proven; overlap skipped when a tag link exists (the decoy B situation); all passing candidates link; method symbols link by overlap but are never zombies; non-exported and test-file symbols are never zombies; an unknown tag gives one diagnostic and no link; links and zombies sorted; `lastCommit` picks the newest file and is null without history; duplicate ids; counts agree with lists; parser diagnostics merged with `source: "parser"`.
  - _Requirements: linker/R1.1, linker/R1.4, linker/R1.6, linker/R2.8, linker/R2.10, linker/R3.1, linker/R3.7, linker/R3.8, linker/R4.1, linker/R4.2, linker/R4.3, linker/R4.4, linker/R4.5, linker/R4.6, linker/R4.7, linker/R4.8, linker/R5.1, linker/R5.2, linker/R5.3, linker/R5.4, linker/R5.5, linker/R5.6, linker/R5.7, linker/R5.8, linker/R5.9, linker/R5.10, linker/R7.1, linker/R7.2, linker/R7.3, linker/R7.4_

- [ ] 4. Accuracy, `linkProject`, accuracy test, remaining properties and self-run
  - Create `src/linker/accuracy.ts` (`scoreAgainstTruth`, sets, ratios of 1 on empty denominators) and `src/linker/index.ts` (re-exports and `linkProject` with the single guard and `link-failed`).
  - Add `tests/linker/accuracy.test.ts`: small examples (perfect, one false positive, one miss, empty truth and empty findings give 1, duplicate truth entries, per-class and overall sums).
  - Add `tests/linker/planted-accuracy.test.ts`: run `linkProject` on `tests/fixtures/planted`, load `expected.json`, call `scoreAgainstTruth`, print with `console.log` one line `linker accuracy: precision=<x> recall=<y>` for each of ghost, zombie, unproven and overall (label each line, for example `ghost`), and assert only that every number is a real value between 0 and 1 and that overall precision and overall recall are each at least 0.8. Do not change THRESHOLD or `expected.json` to pass; report the numbers if the assertion fails.
  - Add `tests/linker/link-properties.test.ts` with fast-check over generated requirements (unique ids) and a small generated index: `link` never throws; every requirement appears exactly once with exactly one status; two runs give deep-equal body maps and identical `JSON.stringify`; no ghost has code links; counts agree with the lists.
  - Add `tests/linker/self-link.test.ts`: run `linkProject` on this repository's root, check that nothing throws, that the body map has requirements for `linker/` and `indexer/` specs, that every ghost and unproven entry has a non-empty id, a file and a line of at least 1, that every zombie has a symbol, a file and a line of at least 1, and that diagnostics have source, code, message and file. Tolerate `unknown-requirement-tag` diagnostics, since fixtures and tests mention ids on purpose. Add a `linkProject` test on a temp directory that has no `.kiro` and no sources (empty body map, no throw).
